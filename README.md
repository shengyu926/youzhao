有时候，你只差一句能发出去的话；有时候，真正困住你的，是不知道这段关系还值不值得继续。

有招从你眼前的问题开始：先听懂你在意什么，再分清实际发生的事、可能的解释和还不知道的部分。需要回复，就先给一句自然的话；需要判断，就结合双方的意愿、投入和现实条件，帮你选择下一步。

它会跟着你的表达习惯调整长短和语气，可以白话一点，也可以带点幽默。难受的时候认真听，着急回复的时候先解决眼前的问题，不要求你先填完一张性格问卷。

有招采用通用 Agent Skills 目录结构，面向豆包工作、Codex、Claude Code 和提供自定义技能入口的 Claude 网页环境。**当前为预览版：本地格式、脚本与打包检查已完成，各宿主的实际调用仍需分别验证。** 详见[平台测试表](docs/平台测试表.md)。

## 它能帮你解决什么

| 你遇到的问题 | 有招会怎么帮 |
|---|---|
| 不知道这句话怎么回 | 先给一条能直接发送的回复，需要时再说明时机和后续分支 |
| 想认识、邀约、表白或推进关系 | 结合熟悉程度与实际反馈，设计具体、可拒绝的下一步 |
| 看不懂对方，或在多人之间犹豫 | 看行为、互惠、承诺与现实条件，区分事实和猜测，不替别人读心 |
| 聊天太长、截图太多 | 在宿主支持读取的前提下，核对说话人、顺序和关键事件；模糊的地方不补造 |
| 知道怎么说，却怕临场卡住 | 一轮一句进行对话陪练，结束后回看表达和改进点 |
| 按建议做了，却不知道下一步 | 根据真实反馈复盘，修正判断和行动，避免重复投入 |
| 异地、作息不同、联系频率谈不拢 | 帮你把期待说具体，协商联系和见面，而不是安排机械打卡 |
| 遇到冷淡、争吵、失衡、分手或复合 | 梳理情绪与利弊，讨论推进、修复、降低投入或退出的选择 |
| 对方聊星座，自己接不上话 | 提供自然接梗、轻松调情和延伸话题，尊重对方信或不信 |
| 看不懂上升、金星、夫妻宫、四化 | 解释传统术语，辅助阅读清楚的用户盘面，分开盘面文字与文化解释 |
| 希望以后少重复交代背景 | 在宿主支持 Python 和持久存储、且你明确同意后，维护可查看、更正、暂停、撤销和删除的精简档案 |

## 说话自然一点，也把事情想明白

你可以直接说：

```text
她回我“最近有点忙”，我不想显得催，帮我回一句。

这段太像报告了，短一点，用我平时的口气。

陪我练一次邀约，你演对方，一轮一句，结束后再点评。

我按上次建议做了，这是实际反馈，帮我调整下一步。
```

不强行叫“宝”“姐妹”或“兄弟”，不按性别和 MBTI 猜你的说话习惯，也不把每次回答都写成固定五段分析。幽默看场合，建议尽量落到一句话、一件事或一个明确选择。

下面是**说明用的示例，不是效果保证或宿主实测记录**：

> 对方：“我是处女座，比较挑。”  
> 已有玩笑氛围时可以接：“你主要挑吃的，还是挑陪你吃的人？”  
> 刚认识时可以轻一点：“吃饭这方面也挑吗？”

> 对方：“别再联系我了。”  
> 这时就认真收住：“明白，我尊重你的意思，不再打扰。”

## 不预设你应该爱谁

有招支持讨论不同性取向、性别身份和建立在知情同意基础上的关系形式，包括异性或同性约会、双性恋、泛性恋、无性恋、跨性别与非二元用户的关系经验，也可以讨论单身约会、长期伴侣、婚姻、异地、再婚、跨文化关系和知情同意的非单偶关系。

谁主动、怎么表达、想要什么样的关系，都从具体的人和双方意愿出发。MBTI、依恋类型或星座可以成为话题与提问线索，不能替代实际行为，也不能绕过明确拒绝。

## 星座和紫微，怎么用在聊天里

这部分适合想聊这些话题、了解术语或借此探索偏好的用户。你可以说：

```text
她说我们星座不合，帮我看看是在开玩笑还是婉拒。

上升、月亮和金星分别是什么意思？讲白话一点。

这张紫微命盘里的夫妻宫和四化是什么意思？看不清的地方别猜。

他一周不回复，我总拿星座替他找理由，帮我看现实情况。
```

有招可以把象征性描述转成开放的问题，例如从“喜欢稳定”聊到“你忙的时候希望怎么保持联系”。判断关系时仍看实际相处：是否尊重、是否兑现承诺、是否愿意投入。

**v0.2.0 不内置自动排盘引擎。** 本包提供术语、话题、盘面阅读和可选工具协作规则；只有宿主另有真实可用的排盘工具，并成功返回结果，才称完成排盘。没有出生时刻不补造上升、宫位或确定命盘。

工程候选包括 [iztro](https://github.com/SylarLong/iztro)、[Astronomy Engine](https://github.com/cosinekitty/astronomy) 等，当前仅做来源登记与适配说明，**尚未集成**。社区 Stars 不代表预测效度；传统文化解释不用于断定忠诚、婚期或关系结局。详见[星盘工具与宿主适配](references/practical/星盘工具与宿主适配.md)。

### 豆包工作

1. 进入实际支持技能上传或导入的**工作环境**；普通“对话”入口可能拒绝 ZIP。
2. 上传根目录 ZIP，请求安装有招。若环境不支持安装，应明确报告，不把读取附件当成安装。
3. 在 `/` 或已安装技能列表检查 `youzhao` / `Youzhao · 有招`。
4. 新开任务，选中有招，用虚构场景检查调用与参考文件读取。

旧名适配包曾有用户提供的豆包菜单截图；有招更名版及新增能力仍待复测。账号、手机、电脑网页与客户端分别验证，不承诺所有账号有相同入口或跨设备自动同步。

### Codex 与 Claude Code

将完整的 `youzhao` 目录安装到当前宿主的技能发现目录，保留 `SKILL.md`、`references`、`scripts` 和许可文件。Claude Code 可尝试 `/youzhao`，Codex 可显式请求使用 `$youzhao`。

具备仓库下载和本地写入能力的助手，可使用这条安装请求：

```text
请从 https://github.com/shengyu926/youzhao 下载并安装 youzhao Skill，使用适合当前宿主的技能目录。保留 references、scripts 和许可文件，不覆盖或删除已有用户档案；不支持安装就明确说明，不要只读文件后声称安装成功。
```

这条请求依赖宿主执行能力，不是保证所有平台都能运行的安装器。

在账号提供的自定义技能管理入口上传带 `youzhao/` 外层目录的文件夹 ZIP。是否能上传、执行 Python 或持久保存数据，取决于账号和组织策略。临时执行环境里的文件不能直接视为永久记忆。

## 第一次使用，不必填问卷

安装并确认可调用后，可以直接说：

```text
请使用有招帮我看看这段聊天，先给我一句回复，再说说你怎么判断。
```

也可以用自己的方式讲：

```text
我们怎么认识的：
现在大概是什么关系：
最近发生了什么：
我希望推进、修复，还是退出：
眼下最需要帮忙的一件事：
```

这些只是可选线索，不知道的可以留空。MBTI、主观评分、出生资料和长期建档都不是开始使用的条件。有招只补问会改变当前建议的信息。

## 聊天记录与长期档案

### 分析聊天材料

在宿主支持的范围内，可以粘贴文字、上传清楚的截图或提供自己取得的导出文件。有招会先核对双方说话人，区分原文、转述、推测与未知。ChatLab 是可选协作工具，只分析用户已提供或导入的数据，不负责读取、解密或导出聊天软件数据库。

### 经同意保存精简背景

需要跨任务复用时，先确认宿主具有 Python、文件写入和真实持久存储能力，再得到你的明确同意。脚本支持查看、更正、暂停、恢复、撤销、忘记对象和删除；不保存整份聊天，不因一句“记住了”就宣称写入成功。

没有可靠存储时，仍可在当前会话使用；不会把临时文件说成永久记忆。出生时间和地点也不因你同意保存关系档案而自动入档或外传。

更新技能不应覆盖档案。旧 `goutoujunshi` 数据不自动读取或迁移；技术配置与迁移边界见[更新与旧版迁移](docs/更新与旧版迁移.md)。请勿将私人聊天、出生资料、数据库或验证码提交到公开仓库。

## 建议如何产生

```text
你眼前的问题或材料
  → 理解情绪、目标与需要立即处理的事
  → 核对事实，保留未知
  → 按需读取相关指南
  → 结合双方意愿、实际行为与现实条件
  → 给出一句回复、一个选择或下一步行动
  → 有真实反馈时再调整
```

这是内部判断思路，不是每次都要展示的固定报告。星座、紫微和人格标签只能提供话题或待核实的联想，不能代替当事人的表达。

## 设计原则

1. **先解决眼前的问题。** 需要回复就先给一句话，难受时先理解发生了什么。
2. **行为比标签可靠。** 不凭 MBTI、性别、星座或一张命盘替别人读心。
3. **沟通要双向。** 可以主动，也尊重拒绝、退出和改变主意。
4. **建议能落地。** 说明关键条件和代价，用真实反馈修正判断。
5. **表达跟着人走。** 白话、自然、适量幽默，不强行亲昵或套固定流程。
6. **工具状态要真实。** 没读到、没算出、没保存，都直接说清楚。
7. **危险情境先处理安全。** 不用普通话术或文化解释掩盖胁迫、暴力和跟踪。

## 开发与验证

以下命令用于源码仓库，不是豆包聊天框里的安装指令。使用 Python 3.10 及以上；档案与打包脚本不依赖第三方 Python 包。先建立仓库内的 `tmp` 目录，再运行：

打包器拒绝覆盖同名发行文件。测试覆盖同意门禁、独立档案、更正撤销、暂停删除、旧数据不变、包内容完整性和两种布局一致性。本地测试不能代替模型行为和跨平台运行验收。
